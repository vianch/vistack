# teach: build understanding the user keeps

Success is the user explaining or applying the idea afterward, not having read an
explanation. So teaching is a loop with the user in it, built from this codebase.

## Loop

1. **Find the level.** Infer it from how they asked and the conversation so far. Ask one
   calibrating question only when the gap could be large ("have you used React context
   before?").
2. **Anchor.** One sentence on what it is and the problem it solves. The problem first:
   an idea sticks to the need it answers.
3. **Show it here.** The smallest real example in this repository, by `file:line`. Fall back
   to a minimal standalone example only when the repository has none, and say so. Where this
   repository departs from the textbook version, teach its version and name the difference.
4. **One new idea per step.** Connect each to the step before. Define a term before using it.
   Mark a simplification as one ("simplified: retries also back off"). Use an analogy only
   where it maps exactly, and say where it breaks.
5. **Check by applying, not repeating.** Ask one question the user answers by using the idea:
   predict what happens if a line changes, spot the bug, choose between two options. Wait for
   the answer. Correct the specific misconception, not the whole topic.
6. **Practice, when they want it.** A small exercise in this repository with a hint ladder:
   a nudge, then a pointer to the line, then the answer.
7. **Recap.** Three bullets and two files to read next.

Keep each step short, around 150 words, so the user can steer. "Explain it fully" switches to
one structured explainer with the same order. "Quiz me" starts at step 5.
